# 核心服务监督与恢复复核

关联 #4、#5。复核基线为 #5 的 `c7f1760`，本次仅完善公开桌面外壳的恢复行为，不引入手机、账号或商业运行时实现。

## 已修复

- 同一运行时地址和令牌被启动事件、健康检查重复报告时，保留连接身份；不会把仍在处理的 REST 请求误判成已切换，也不会断开现有 WebSocket。
- 并发 GET 传输失败共享一次恢复。请求取消后不再启动恢复；恢复过程中取消后也不会重发。写请求默认不重发，并明确显示执行状态未知。
- 核心重启并发布新端点后，实时事件连接使用新地址和令牌重新建立；忽略旧连接的迟到回调。显式清空端点和主动关闭仍结束订阅。
- 核心启动失败与手动重启之间的竞争不再吞掉重启请求；退避等待也检查请求代次。停机、不可恢复启动失败会及时解除等待，状态快照不再附带失效端点。
- 健康探测必须读到完整 HTTP 状态行；零碎响应按总时间限制处理，避免每读到一个字节就重新延长探测。
- 运行时面板订阅后读取当前状态；新事件优先于迟到快照，卸载后迟到的订阅注册会立即清理。
