## 1. 不变的边界（来自 2026-10-22 的确认）

- **管理层，不是内核：** Personal Agent 是新增的管理层。长期会话、记忆、压缩、自进化、用量管理**只作用于它自己**。
- **不碰被指挥的对象：** 被指挥的 Agent / CLI / 手机保留各自的模型、权限、上下文和计费，助理不改写它们的配置或记忆。
- **只用 Lom 模型：** 主模型只用 Lom 账号模型，扣账号订阅额度。Jev 只帮忙选工具，不替代主模型。
- **不伪造：** 没有真实闭环的能力一律显示“未接入”。不把“已发送”说成“已送达”，不把“已设置”说成“已执行”。

## 2. 总体结构

```
            ┌──────────── 入口层 ────────────┐
 你 ──飞书── │ 飞书网关（openclaw-lark 适配）   │
 你 ──微信── │ 微信网关（个人微信 iLink 协议）  │──┐
 你 ──桌面── │ 悬浮面板（PA02，已合并）         │  │  统一消息信封
            └─────────────────────────────────┘  ▼
                                   ┌─── 会话路由：同一 pa_session_id，按序入队 ───┐
                                   │                                              │
                                   ▼                                              │
            ┌──────── 快思考层（Jev 路由） ─────────┐                             │
            │ 规则/缓存直达 → 本地工具目录筛候选     │                             │
            │ → Jev 选工具 → 只加载选中的工具说明    │                             │
            └──────────────────┬────────────────────┘                             │
                               ▼                                                  │
            ┌──────── 主 Agent（Lom 模型） ─────────┐  ←── OpenClaw 式记忆层       │
            │ 计划、参数、调用工具、最终答复         │      SOUL/USER/TOOLS/AGENTS/   │
            └───┬─────────────┬──────────────┬──────┘      IDENTITY/MEMORY + 日记   │
                ▼             ▼              ▼                                     │
          飞书能力层      调度桥           定时任务          ← 自进化层（纠正即学习） │
          （你本人身份）  （任意会话/手机）  （按任务按通道推送）                    │
                              │                                                    │
                              └── 完成事件 ──► 只回到助理会话（不推 IM） ───────────┘
```

### 2.1 运行位置（决定 A：全部在本地）

| 组件 | 跑在哪 | 说明 |
|---|---|---|
| 飞书、微信网关 | **桌面 lom-core**，作为 Personal Agent 的一个模块 | 飞书用事件长连接（WebSocket），微信用长轮询，都是电脑主动连出去，**不需要公网地址或服务器** |
| 会话路由、消息队列、投递回执 | 桌面 lom-core | 跨通道按顺序处理，防重复；推送失败只重发消息 |
| 主 Agent、记忆文件、调度桥、定时任务执行 | 桌面 lom-core | 记忆文件、你的会话、本机 CLI、手机配对都在电脑上 |
| 凭据 | 本机 SecretStore（系统钥匙串） | 飞书用户令牌、机器人密钥、微信登录凭据**只存在你电脑上**，不上传 Lom 服务器 |

这样做的结果（需要你知道）：
- **电脑关机或休眠时，飞书、微信都收不到回复。**
  - 飞书长连接断开期间，平台会在一段时间内重试推送事件。电脑恢复后能补收多少、补收多久以前的，要实测；
  - 微信长轮询断开期间的消息，恢复后能否补取，也要实测；
  - 补收到的旧消息，先回一句“刚才电脑离线，现在处理”再执行。超过一定时间（默认 2 小时，可设）的旧消息只回状态、不自动执行，免得半夜的指令早上突然被执行。
- **定时任务只在电脑开着时执行。** 到点时电脑离线，记为“未执行（电脑离线）”；电脑恢复后不自动补跑，在助理会话里列出错过的任务。
- **前提：** 电脑要允许 Lom 在后台常驻。关窗口不退出，核心保持运行。社区贡献的 rfdiosuao/lom-desktop#5（“关窗不退核心”）可以参考。
- 以后如果想让电脑关机时也有回复，再另立需求把网关迁到云端；本架构的网关接口按“可替换”设计，不写死在桌面。

## 3. 入口层

### 3.1 统一消息信封

三个入口的消息都转成同一结构，再进入助理会话：

```ts
interface InboundEnvelope {
  envelopeId: string;          // 去重键：通道 + 平台消息 ID
  channel: 'feishu' | 'weixin' | 'desktop';
  paSessionId: string;         // 同一助理同一会话
  sender: { platformUserId: string; isOwner: boolean };   // 只有绑定的主人能下指令（#41）
  text: string;
  attachments: { kind: 'image'|'video'|'file'|'voice'; localPath?: string; name: string; bytes: number }[];
  replyContext: { channel: string; chatId: string; messageId: string; replyToken?: string };  // 原路回复用
  receivedAt: number;
}
```

- **回复原则：** 默认只回到消息来源的那个通道（#91），不广播到所有通道。
- **主人校验：** 非主人发来的消息不执行任何指令，只记录（#41）。
- **自我隔离：** 机器人自己发出的消息不会再触发任务。

### 3.2 飞书网关

- **收消息与流式回复：** 参考 `larksuite/openclaw-lark`。
  - 用事件订阅（WebSocket 长连接）收消息；
  - 用**同一张交互卡片持续更新**实现流式回复，合并过密的更新并限流；
  - 成功、失败、取消都要结束流式状态。
- **身份：**
  - 机器人身份负责收发消息；
  - **你本人的身份**（OAuth 用户令牌）负责操作文档、日历、表格、审批等（需求 4）；
  - 用户令牌存在本机 SecretStore（系统钥匙串），过期自动刷新；刷新失败就提示你重新授权，不静默降级成机器人身份。
  - 飞书 OAuth 回调用本机回环地址（`http://127.0.0.1:<端口>/callback`）接收，不需要服务器。
- **媒体：** 图片、视频、文件下载为真实文件，交给桌面，生成统一附件。助理生成的文件**上传文件本体**回到飞书，不发电脑路径。

### 3.3 微信网关（个人微信）

- **协议：** 首选腾讯官方的 `Tencent/openclaw-weixin`（iLink 机器人协议），流程是扫码登录、长轮询收消息、媒体上传下载、输入状态。
  - lom-core 是 Rust，优先评估 `corespeed-io/wechatbot` 的 **Rust SDK** 直接接进核心；扫码登录的二维码显示在桌面悬浮面板的“连接”区；
  - `wong2/weixin-agent-sdk` 作为媒体处理和 Agent 桥接的参考。
- **语音：** 微信语音多为 SILK 格式，先解码成 WAV 再识别。解码失败和识别不清要分开提示。
- **主动推送的限制：** 主动给你发消息依赖平台的回复令牌（context_token）有效期。
  - 令牌过期时，推送记为“推送失败：需要你先发一条消息唤醒”；
  - 不删长期会话，也不重跑任务；
  - 具体时效要实测。
- **凭据分开管理：** 微信凭据、轮询游标、回复令牌、模型上下文四样分开存，任一失效都不影响另外三样。

## 4. 快思考层：Jev 路由（只给 Personal Agent 用）

### 4.1 目标

飞书有几百个工具，不能全塞给主模型。快思考层要**很快判断出要用哪几个工具，直接开始调用**，减少你的等待。

### 4.2 流程（对应 #99）

```
消息 → ① 规则/缓存直达（固定指令、正在进行的任务、最近成功的同类请求）
     → 未命中 → ② 本地工具目录筛候选（关键词 + 域）
     → 候选太多或有歧义 → ③ Jev 判断：选哪几个工具、是否需要派活
     → ④ 只把选中工具的说明和参数格式交给主模型 → 主模型执行
```

1. **工具目录：**
   - 接入或升级飞书插件、调度桥、手机工具时，生成一份轻量目录：工具 ID、一句话用途、所属域（文档 / 日历 / 表格 / 审批 / 消息 / 调度 / 手机 …）、权限级别、说明版本；
   - 完整的参数格式另存，按需加载。
2. **规则和缓存：**
   - 例如“看看 X 会话进度”直接命中调度桥的查询工具；
   - 缓存按工具版本和授权变化失效；
   - **执行时仍重新校验权限**。
3. **Jev 拿到的信息：** 当前请求、必要的近期任务信息、候选工具的一句话描述。**不给**整段历史、全部工具正文和密钥。
   - 互斥的用单选；
   - 可以同时要的（文档 + 日历 + 表格）用多选，批量判断。
4. **Jev 只是建议：**
   - 保留你的原话和限制，不改写成意思更窄的指令；
   - 没把握、超时或漏选时，由主模型自己补查，**不重复执行已经做过的动作**；
   - Jev 不可用时整条链路仍能工作，只是慢一些。
5. **要实测，不承诺必快：** 对比三种路径：无 Jev、按需 Jev、规则/缓存。测：
   - 首字时间和全程 p50 / p95；
   - 调用正确率、重试次数；
   - token 和成本。

   先观察，数据证明更快再默认打开。

### 4.3 并行开工

- Jev 选出的工具如果是**只读且互不依赖**的（例如同时查日历和查文档），可以并行发起，进一步缩短等待；
- 写操作仍按主模型计划顺序执行。

## 5. 主 Agent 与 OpenClaw 式记忆

### 5.1 文档（每位助理一套，存在 PA02 已有的私有目录里）

| 文件 | 内容 | 谁写 |
|---|---|---|
| `SOUL.md` | 灵魂：性格、语气、价值观 | 你；自进化只能提建议，不改 |
| `USER.md` | 关于你：偏好、习惯、常用联系人、工作方式 | 你，以及你纠正时自动追加（见 §8） |
| `TOOLS.md` | 工具使用说明与经验：哪个飞书操作怎么做、哪个会话负责什么 | 自进化自动维护 |
| `AGENTS.md` | 行为规则：什么必须确认、什么可以直接做 | 你；自进化可追加“工作方法”小节 |
| `IDENTITY.md` | 名字、身份 | 你 |
| `MEMORY.md` | 长期记忆：经过整理、反复用到的事实和约定 | 助理整理、你可编辑 |
| `memory/YYYY-MM-DD.md` | 日记：当天发生了什么、做了什么决定 | 助理自动追加 |

### 5.2 记忆机制（参考 OpenClaw，按 Lom 边界改造）

1. **会话开始或重新加载时：**
   - 读 SOUL / IDENTITY / USER / AGENTS / TOOLS / MEMORY，加上**今天和昨天的日记**；
   - 有界注入：单文件 16 KB、总量 48 KB，超了只注入摘要并标明来源；
   - 记录每个文件的内容哈希，用法同第一阶段方案 §4.4。
2. **写日记：** 每完成一件事、做出一个决定、你纠正一次，就在当天日记追加一行（时间、事、结果、来源消息）。
3. **压缩前先存：** 长期会话快到上下文上限、要压缩之前，先让主模型把这段里值得长期保留的内容写进 `MEMORY.md` 或当天日记，再压缩（#106、#92）。压缩只替换模型看到的内容，原始记录保留。
4. **按需检索：**
   - 你问“上周跟谁说过 X”时，按关键词、时间检索日记和 `MEMORY.md`，命中片段注入当前轮（#108）；
   - 第一版用关键词加时间，向量检索以后再评估（#140）。
5. **安全：** 记忆和文档都是不可信资料，不能提升权限，不能绕过确认（第一阶段方案 §4.5）。

## 6. 调度桥：指挥任意会话（需求 2、5）

### 6.1 可指挥的对象

| 对象 | 怎么派活 | 怎么知道完成 |
|---|---|---|
| 工作台 Lom 会话、外部 CLI（Codex、Claude Code 等） | 向该会话发一条新消息（核心 `/api/conversations/:id/messages`） | 核心的 `turn.completed` 事件 |
| OPC 团队 | 发给团队 Leader（团队消息接口） | 团队任务 / 消息变化事件 |
| 已配对手机 Agent | 复用总指挥的 `phone_task_start`，经云端中继 | 手机会话状态同步（PHONE-TEAM-01 已有） |
| 手机子代理 | PHONE-01 的子代理定义；只能控制启停，不立即启动任务 | 同上 |

### 6.2 助理可用的工具

只在助理会话里提供：

- `session_list(filter)`：列出你账号下的会话，带标题、Agent、状态、最近更新时间。
- `session_read(id, since?)`：读取有界的最近消息和执行状态。
- `session_send(id, text, attachments?)`：派活。
- `session_stop(id)`：停止。属于高风险，需要你确认。
- `phone_task(device, text)`：派活给手机。

### 6.3 授权与安全

- **默认可派：** 不逐个授权，你账号下的会话都能派（需求 5）。
- **必须你确认：** 删除、对外发布（发帖、发邮件、发消息给别人）、付款、停止正在跑的任务、修改别的会话设置。确认请求发到你当前所在的通道（飞书卡片按钮、微信回复“确认 / 取消”、桌面弹窗）。
- **不改对方：** 不读写对方的记忆文件，不修改对方的模型、权限、配置。

### 6.4 完成通知（需求 2）

- 目标会话完成或失败后，往**助理会话**里写一条“某会话已完成 / 失败 + 摘要”，**不推飞书 / 微信**。
- 你下次在任何通道跟助理说话时，它都知道结果；你也可以直接问“刚才那件事怎么样了”。
- 幂等：同一派活只通知一次。派活的幂等键 = 助理本轮 ID + 目标会话 ID，防止重复发送。

## 7. 定时任务：按任务按通道推送（需求 3，对应 #115）

### 7.1 数据结构

```ts
interface PersonalSchedule {
  id: string;
  assistantId: string;
  prompt: string;
  cron: string;
  enabled: boolean;                                   // 任务启停
  push: { feishu: boolean; weixin: boolean };         // 推送开关，与启停互相独立
  lastRun?: {
    at: number;
    run: 'done' | 'failed' | 'skipped_offline';
    delivery: { feishu?: DeliveryState; weixin?: DeliveryState };
  };
}
type DeliveryState = 'not_pushed_off' | 'sent' | 'failed' | 'pending_token';
```

### 7.2 规则

- **两个开关互不影响：**
  - 关推送 ≠ 停任务：静默执行，结果留在助理会话和任务记录里，可以随时查；
  - 停任务也不抹掉原来的推送选择。
- **执行和投递分开记录：** 例如“已执行 · 未推送（开关关闭）”“已执行 · 推送失败”。推送失败只重发消息，**不重跑任务**。
- **发送前再核对：** 推送前读取最新开关，运行中改了设置就按新设置；历史上静默的结果不擅自补发。
- **助理也能改开关：** 你可以说“这个任务继续跑但别给我发微信”。
  - 助理先定位任务、读当前状态，再修改，然后回报真实结果；
  - 它**不能擅自重新打开**你关掉的推送；
  - 每次修改记录操作者、时间、前后状态。
- **需要审批时：** 任务执行中如果要确认，仍然等你确认，不因为静默就自动批准。

## 8. 自进化层（参考 Harness2，决定 B：全部自动生效）

原则：**大部分时候它学得对，就直接用；少数学错了，你纠正一次它就改。** 不设“每条经验等你同意”这一步。

### 8.1 两个来源，都自动生效

1. **你的纠正：** 例如“不对，周报要发到 X 群”“以后这种事先问我”“这个文档用表格格式”。
2. **助理自己总结：** 任务完成或失败后自己复盘，例如“这个飞书表格每次都要先筛选状态列”“Codex 会话做前端比 Claude Code 快”。

### 8.2 流程

```
纠正 / 任务结束 → 抽取经验（触发条件 / 经验内容 / 证据：哪条消息、哪次任务、结果如何）
      → 分类：用户偏好 → USER.md；工作方法 → TOOLS.md / AGENTS.md「工作方法」小节；
               人格相关 → SOUL.md 的「近期调整」小节（不改原有正文）
      → 冲突处理：和已有经验矛盾时，新的覆盖旧的；你的纠正永远优先于助理自己总结的
      → 底线检查（见 8.4）：碰底线的不生效，只记日志
      → 直接生效：写入对应文件，生成新版本 vN（保留 vN-1）
      → 告诉你一声，不等回复：
           你纠正的 → 当前通道回一句“记住了：……”
           自己总结的 → 不打断你，记在当天日记里；桌面面板“记忆日记”区可看全部
      → 后续观察：同一条经验又被你纠正 → 用你的版本覆盖，并把这条标为“曾学错”
```

### 8.3 与 Harness2 的对应

| Harness2 机制 | Lom 做法 |
|---|---|
| 经验库（cue / lesson / evidence） | 每条经验都有触发条件、内容、来源证据，存 `TOOLS.md` / `AGENTS.md` / `USER.md`，并在 `memory/lessons.jsonl` 留结构化记录（来源：你纠正 / 自己总结） |
| 候选与基线对照 | **不设人工审批**。用“你的纠正”当最终裁判：自己总结的经验先用，被你纠正就覆盖。同一类经验反复被纠正时，降低该来源的自信度，下次同类情况先按你的旧纠正走 |
| 版本树 | 每次生效都生成版本，可一键回滚到任意历史版本；也可以直接说“把昨天学的那条撤掉” |
| 不改模型权重 | 只改提示、文档、工具策略和技能；不改被指挥的 CLI 配置（#164 的边界） |

### 8.4 唯一的底线（不需要你审批，直接拦）

经验涉及以下内容时**不生效**，只在日志里记一条“这条没采用，原因：……”，也不来问你：

- 放宽确认规则（例如“以后删除不用问了”）；
- 扩大工具、文件、手机、IM 的权限范围；
- 修改密钥和授权。

这几类只有你**明确用一句话说出来**（例如“以后删除这个文件夹里的临时文件不用问我”）才会改，而且改的是设置，不是经验。原因：这几类一旦学错，后果不是“回答不合心意”，而是删了东西或发错了消息，纠正也来不及。

## 11. 风险

1. **个人微信的协议与政策：** iLink 机器人协议的可用范围、频率限制、主动推送时效都要实测。平台规则变化可能导致功能受限，要有“微信不可用时改从飞书推送”的退路。
2. **飞书“所有能力”很大：** 必须按域逐项列覆盖表、标实测状态，不能因为 CLI 有命令就宣称可用。
3. **电脑关机就没有回复：** 网关在本地的直接代价，离线补收能力要实测。设置里让你看到授权了什么，随时能撤。
4. **Jev 不一定更快：** 必须有测速数据才默认开启。
5. **自动生效的经验可能有误：** 靠你纠正覆盖、版本回滚和“曾学错”标记兜底；涉及权限和确认的三类由底线自动拦截。
